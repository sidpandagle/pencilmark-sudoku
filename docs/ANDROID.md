# Pencilmark — Local Android build

Everything builds locally. No EAS cloud, no Expo account. `android/` is generated by `expo prebuild` and git-ignored. Never edit it by hand: change `app.json` or a config plugin in `plugins/` instead.

In this CLI version `sdkmanager` is a thin wrapper around the new `android` CLI. Licenses are accepted at install time, and `sdkmanager --licenses` reports "no longer needed". To list or install packages:

```powershell
android --sdk=D:\dev\android-sdk sdk list                       # installed + available
android --sdk=D:\dev\android-sdk sdk install "platforms/android-36"
```

Package names use `/`, not `;`. In Git Bash, `sdkmanager.bat "a;b"` gets split at the `;`. In PowerShell, `sdkmanager "platforms;android-36"` also works.

## Environment

User-level variables (picked up by new terminals):

- `JAVA_HOME=D:\dev\jdk-17`
- `ANDROID_HOME=D:\dev\android-sdk`
- `PENCILMARK_UPLOAD_PROPERTIES=D:/dev/keys/pencilmark-upload.properties` (a path only, not a secret)
- User `PATH` starts with `platform-tools`, `emulator` and `cmdline-tools\latest\bin`.

Caveat: the **machine** PATH still lists `C:\Program Files\Java\jdk-11.0.16+8\bin` and `C:\platform-tools` (adb 36.0.2), and Windows puts the machine PATH before the user PATH.

- Gradle uses `JAVA_HOME`, so builds get JDK 17 anyway.
- Bare `java` and `adb` in a new shell may still be the old ones. Two adb versions fighting cause "adb server version doesn't match" restarts.
- Fix: in every shell you build from, run:

```powershell
. .\scripts\android-env.ps1     # dot-source: sets JAVA_HOME, ANDROID_HOME, prepends JDK 17 + SDK tools to PATH
```

Note: user-level `JAVA_HOME` now points at JDK 17. If another project (for example Maven) relied on `JAVA_HOME` being JDK 11, set it per shell for that project.

## Emulator

- AVD `Pixel_API_35`: pixel_7 profile, Android 15 (API 35), google_apis x86_64, 4 GB RAM, 6 GB data, hardware keyboard on.
- Files are in `%USERPROFILE%\.android\avd\Pixel_API_35.avd`.
- Acceleration: `emulator -accel-check` reports `WHPX(10.0.26100) is installed and usable`.

```powershell
. .\scripts\android-env.ps1
emulator -avd Pixel_API_35                     # with a window
emulator -avd Pixel_API_35 -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect   # headless
adb wait-for-device; adb shell getprop sys.boot_completed   # "1" when ready
adb emu kill                                   # stop it
```

Verified on 2026-10-11: the headless cold boot with `swiftshader_indirect` reached `sys.boot_completed=1` after about **12 minutes** (first boot, CPU rendering).

- Later boots use the quick-boot snapshot and are much faster. Do not pass `-no-snapshot-save` if you want the snapshot saved.
- With a window, try `-gpu host` for faster rendering.
- The app targets API 36 and runs on the API 35 image (minSdk 24).

## Build

Run prebuild first, and again after any change to `app.json`, `plugins/` or native dependencies:

```powershell
. .\scripts\android-env.ps1
npx expo prebuild --platform android --clean
```

The first Gradle run downloads Gradle 9.3.1 and the Maven dependencies (about 1 GB, needs internet), so it takes ~15–30 minutes. Later builds take ~2–5 minutes.

**On this laptop, a full 4-ABI release build compiles a lot of C++ and took over 90 minutes.** Two tips:

- Don't run the emulator during the build (the session's low-memory guard stopped one build).
- For a quick emulator test, build only x86_64: `.\gradlew assembleRelease -PreactNativeArchitectures=x86_64`. Build the Play AAB with all ABIs (the default).

### Windows build pitfalls (both hit on this machine, both fixed)

1. **`The filename, directory name, or volume label syntax is incorrect` / `Unexpected JSON token ... '('` in `settings.gradle`.** Gradle runs `node` and `cmd /c npx ...` and reads their output. Any cmd.exe AutoRun script that prints text corrupts it. Here the cause was a UTF-8 BOM before `@echo off` in `~/.cmd_prompt.bat`; it was removed, and a backup is at `~/.cmd_prompt.bat.bak-pencilmark`. Check yours with `reg query "HKCU\Software\Microsoft\Command Processor" /v AutoRun`.
2. **`ninja: error: Stat(...): Filename longer than 260 characters`.** CMake 3.22.1's ninja 1.10 isn't long-path aware. Install CMake ≥ 3.31 (`android sdk install "cmake/3.31.6"`, which ships ninja 1.12.1) and keep Windows `LongPathsEnabled=1`. `scripts/android-env.ps1` sets `PENCILMARK_CMAKE_DIR` to the newest CMake, and `plugins/withLocalCmake.js` writes it to `android/local.properties` (`cmake.dir`) during prebuild. A `subst` drive does **not** work: autolinking can't find `package.json` at a drive root.

### Debug APK

```powershell
cd android
.\gradlew assembleDebug
# -> android\app\build\outputs\apk\debug\app-debug.apk
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

`npx expo run:android` also works (it builds, installs and starts Metro). A debug build loads JS from Metro, so it needs INTERNET, which debug builds keep.

### Release AAB (Play upload) and release APK (local test)

```powershell
cd android
.\gradlew bundleRelease
# -> android\app\build\outputs\bundle\release\app-release.aab
.\gradlew assembleRelease
# -> android\app\build\outputs\apk\release\app-release.apk   (install with adb to test the real release build)
```

Check the signature and permissions:

```powershell
keytool -printcert -jarfile app\build\outputs\bundle\release\app-release.aab   # should show CN=Pencilmark Sudoku
& "$env:ANDROID_HOME\build-tools\36.0.0\aapt2.exe" dump permissions app\build\outputs\apk\release\app-release.apk
```

## Release signing

- **Upload keystore:** `D:\dev\keys\pencilmark-upload.jks`. Type JKS, alias `pencilmark-upload`, RSA 4096, valid until 2054-02-26. SHA-256 fingerprint `03:83:C7:3F:FC:4C:9D:30:EB:F8:BB:BE:25:2A:DE:91:09:CE:B3:1B:BA:AD:74:7B:3D:8F:AA:A6:4C:A5:0F:A8`.
- **Secrets:** `D:\dev\keys\pencilmark-upload.properties` holds the store file path, the random store and key passwords, and the alias.
- **Location:** both files are outside the repo. `.gitignore` also blocks `*.jks`, `*.keystore` and `*keystore*.properties`/`*-upload.properties` in case a copy ends up in the tree.
- **Back up both files** (for example in a password manager plus an offline copy). With Play App Signing, a lost upload key can be reset through Play Console support, but that is slow. Never commit them, never paste the passwords into chat or issues.

`plugins/withReleaseSigning.js` (listed in `app.json`) patches `android/app/build.gradle` during prebuild. For each value it checks, in order:

1. environment variable
2. Gradle property (`-PKEY=value` or `%USERPROFILE%\.gradle\gradle.properties`)
3. the properties file named by `PENCILMARK_UPLOAD_PROPERTIES`

The keys are:

| Key | Meaning |
|---|---|
| `PENCILMARK_UPLOAD_STORE_FILE` | absolute keystore path (forward slashes) |
| `PENCILMARK_UPLOAD_STORE_PASSWORD` | keystore password |
| `PENCILMARK_UPLOAD_KEY_ALIAS` | key alias |
| `PENCILMARK_UPLOAD_KEY_PASSWORD` | key password |

If any value is missing, or the keystore file does not exist, the release build is signed with the **debug** key and Gradle logs `[pencilmark] Upload keystore not configured`. Never upload such a build.

## Permissions (offline game)

- `app.json` sets `android.permissions: []` and uses `android.blockedPermissions` to strip permissions an offline game does not need. These include SYSTEM_ALERT_WINDOW, READ/WRITE_EXTERNAL_STORAGE, READ_MEDIA_*, RECORD_AUDIO, CAMERA, location and AD_ID.
- `VIBRATE` stays for haptics.
- `INTERNET` cannot go in `blockedPermissions`, because that removes it from every variant and debug builds need it for Metro. Instead, `plugins/withOfflineRelease.js` writes `android/app/src/release/AndroidManifest.xml` with `tools:node="remove"` for INTERNET. Only **release** builds lose it. Check with the `aapt2 dump permissions` command above.

## Other notes

- `app.json` sets `userInterfaceStyle: "automatic"`. On Android this only takes effect with `expo-system-ui` installed (`npx expo install expo-system-ui`). It was not a dependency when this was written.
- `ios/` is not used. The project targets Android only.
